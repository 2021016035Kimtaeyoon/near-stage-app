# NEAR:STAGE (구 오늘무대)

공연할 곳이 없는 공연자와 손님이 필요한 소규모 공간을 연결하고, 그렇게 만들어진 공연을 지도 기반으로 관객에게 유통하는 3면 마켓플레이스 프로토타입입니다.

백엔드 서버 없이 프론트엔드 목데이터 + `localStorage`만으로 동작하며, 지도 타일(OpenStreetMap) 외에는 어떤 외부 API도 호출하지 않습니다.

## 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:5173`으로 접속합니다.

- **데스크톱**(가로 900px·세로 720px 이상): 화면 중앙에 아이폰 프레임(390×844) 안에서 앱이 렌더링되고, 프레임 왼쪽에 역할 전환 패널이 함께 보입니다.
- **모바일**(그 미만): 프레임 없이 풀스크린으로 렌더링됩니다.

기타 명령어:

```bash
npm run build      # 프로덕션 빌드 (tsc --noEmit 포함)
npm run preview    # 빌드 결과 미리보기
npm run typecheck  # 타입체크만 실행
npm run lint       # ESLint 검사
```

Vercel에는 `vercel.json`이 포함되어 있어 저장소를 그대로 연결하면 별도 설정 없이 배포됩니다.

## 심사 시연 순서 (요약)

자세한 대사와 타이밍은 [DEMO_SCRIPT.md](./DEMO_SCRIPT.md)를 참고하세요. 가장 빠른 길은 다음과 같습니다.

1. 앱을 열면 관객 홈(지도)이 기본 화면입니다. `우리 무대`(브랜드 그라데이션 마커)와 `등록 공연`(외곽선 마커)이 지도와 리스트 양쪽에서 뱃지로 구분되는 것을 먼저 보여주세요.
2. 우상단 톱니바퀴 아이콘(시연자 패널) → **"자동 시연 시나리오 열기"**를 누르면 `/demo` 화면으로 이동합니다.
3. **"처음부터 재생하기"**를 누르면, 공간주가 구인글을 올리는 순간부터 관객이 예약·리뷰를 남기기까지 8단계가 실제 화면 전환과 함께 자동으로 진행됩니다. 화면 상단 자막 바에서 언제든 일시정지·이전·다음·처음부터·재생 속도(0.5x/1x/2x)를 조작할 수 있습니다.
4. 화면 우하단의 보라·주황 그라데이션 버튼(역할 전환기)으로 관객/공간주/공연자 화면을 언제든 수동으로 오갈 수 있습니다. 같은 데이터를 세 개의 눈으로 보는 느낌을 강조해주세요.

## 프로젝트 구조

```
src/
  config/        서비스명·기준 시각·수수료 등 전역 상수 (brand.ts), 탭 구성 (nav.ts)
  types/         전 도메인 타입 정의 (index.ts 한 파일)
  lib/           순수 함수 유틸 — 시드 난수(rng), 그라데이션(gradient), 날짜(datetime),
                 거리 계산(geo), 장비 매칭(match) 등
  data/seed.ts   목데이터 단일 진입점 (실제 데이터는 data/seed/*.ts 여러 파일로 분리되어 있지만,
                 화면 코드는 반드시 seed.ts 를 통해서만 가져옵니다)
  store/         zustand 전역 상태. actions/ 아래 역할별 액션 분리, selectors.ts에 파생 로직
  components/    공용 UI(ui/), 카드(cards/), 지도(map/), 앱 셸(shell/)
  screens/       역할별 화면 — audience/ owner/ performer/ common/ demo/
  routes.tsx     라우트 정의 (해시 라우터)
```

## 데이터 흐름의 핵심 연결

공간주가 구인글의 지원자를 **수락**하면(`src/store/actions/owner.ts`의 `acceptApplication`):

1. 새 `Show`(공연확정 상태, `source: 'own'`)가 즉시 생성됩니다.
2. 정산 레코드가 `정산대기` 상태로 함께 생성됩니다.
3. `demo.highlightShowId`가 설정되어, 관객 지도에서 해당 핀이 팝 애니메이션으로 등장합니다.
4. 구인글은 자동으로 마감 처리됩니다.

이 상태 변화는 전부 전역 스토어에 반영되므로, 역할을 관객으로 전환하는 즉시(새로고침 없이도) 지도에서 확인할 수 있습니다.

## 목데이터 수정 방법

모든 목데이터는 `src/data/seed/` 아래에 있고, `src/data/seed.ts`가 이를 한 번에 모아 `createSeedData()`로 내보냅니다. 화면 코드에는 하드코딩된 데이터가 없습니다.

| 파일 | 내용 |
| --- | --- |
| `venues.ts` | 공간 16곳 (연남 8·상수합정 4·홍대 2·성수 2) |
| `performers.ts` | 공연자 20팀 |
| `shows.ts` | 공연 34건 (우리 무대 22 + 등록 공연 12), `KOPIS_VENUE_INFO` 포함 |
| `posts.ts` | 구인글 6건, 지원 14건, 역경매 3건 |
| `reviews.ts` | 리뷰 40건 (공간/공연 각 20건, 서로 다른 배열로 관리) |
| `social.ts` | 채팅 스레드/메시지, 알림 12건, 정산 8건 |
| `analytics.ts` | 공간별 8주 주간 방문객 통계 (공연 유무 패턴 수동 지정) |
| `reservations.ts` | 관객 초기 예약, 좋아요/팔로우 초기값 |

새 공연을 추가하려면 `shows.ts`의 `OWN`(우리 무대) 또는 `KOPIS`(등록 공연) 배열에 항목을 추가하면 됩니다. 모든 랜덤 값은 `src/lib/rng.ts`의 시드 고정 난수(`makeRng`)로 생성되므로, 새로고침해도 값이 바뀌지 않습니다.

### 기준 시각(DEMO_NOW) 바꾸기

`src/config/brand.ts`의 `DEMO_NOW_ISO` 상수가 앱 전체의 "지금"입니다. 실제 시스템 시각을 쓰지 않으므로 이 값만 바꾸면 "오늘 밤" 필터 등 모든 시간 기반 로직이 그 시각 기준으로 재계산됩니다. 발표 당일 시연자 패널(우상단 톱니바퀴 → 슬라이더)에서 임시로 바꿔볼 수도 있습니다.

## 임의로 결정한 사항

작업 중 스펙에 명시되지 않았거나 여러 해석이 가능했던 부분은 다음과 같이 정했습니다.

- **서비스명**: 최초 "오늘무대"로 시작했으나 작업 도중 "NEAR:STAGE"로 변경 요청을 받아 반영했습니다. `SERVICE_NAME` 상수(`src/config/brand.ts`) 하나만 바꾸면 앱 전체 표기가 바뀌도록 분리되어 있어 이후에도 쉽게 바꿀 수 있습니다.
- **디자인 톤**: 최초 스펙은 다크 테마 기본이었으나, 작업 도중 화이트(라이트) 테마로 전환 요청을 받아 전체 팔레트를 밝은 톤으로 바꿨습니다. 다만 클립 피드의 포스터 배경만은 릴스/틱톡류 몰입형 카드 관례에 따라 의도적으로 어둡게 유지했습니다.
- **공간주 탭 구성**: 스펙의 [B-2]내 공간 관리와 [B-3]가능 시간 관리를 "공간" 탭 하나 안의 세그먼트(정보/장비·조건/가능 시간)로 통합했습니다. 탭 4개(대시보드/공간/구인/정산) 제약과 5개 화면 요구사항을 동시에 만족시키기 위한 선택입니다.
- **가능 시간 그리드**: 요일×시간대 그리드의 시간대를 아침(06–12)·낮(12–17)·저녁(17–21)·심야(21–24) 4개 밴드로 단순화했습니다.
- **채팅 진입점**: 공연자는 공간 상세의 "공연 문의하기"로, 공간주는 지원자 카드의 "채팅" 버튼으로 같은 스레드에 들어갑니다. 관객에게는 채팅 기능이 없습니다.
- **QR 티켓**: 외부 QR 라이브러리를 쓰지 않는다는 제약에 따라 실제로 스캔되는 QR이 아니라, 예약 코드를 시드로 한 결정론적 패턴을 canvas로 그립니다(파인더 패턴 포함, QR처럼 보이는 디자인 목업).
- **클립 좋아요**: 클립 피드의 하트(좋아요)는 공연 예약과 무관한 가벼운 반응으로 보고, 전역 저장소가 아닌 화면 로컬 상태로 두었습니다(새로고침 시 초기화). 좋아요한 공연·팔로우한 팀은 기존과 동일하게 전역 저장됩니다.
- **리뷰 집계 단위**: 공연 상세의 리뷰 탭은 해당 "공연 1건"이 아니라 그 "공간/공연자"에 대해 지금까지 쌓인 모든 리뷰를 보여줍니다. 같은 팀이 같은 공간에서 여러 번 공연하는 경우가 많다는 점을 고려한 선택입니다.
- **반응형 분기 기준**: 데스크톱 프레임 전환 기준을 가로 900px 이상 **AND** 세로 720px 이상으로 잡았습니다(둘 중 하나만 커도 모바일 뷰 유지).
- **자동 시연 구현 방식**: 각 단계는 실제 모달 클릭을 자동화하는 대신, 그 클릭이 만들어낼 실제 store 액션(구인글 생성, 지원, 수락, 예약, 리뷰 작성 등)을 직접 호출하고 그 결과 화면으로 실제 라우팅합니다. 결과 데이터는 100% 실제이며(새 공연·예약·리뷰가 진짜로 생성됨), 생략되는 것은 모달이 열리고 닫히는 애니메이션 연출뿐입니다.
